# PropFlow V2 ユーザー画面 受入テスト

## テスト環境

本番DBは使用しない。`DATABASE_URL` のDB名に `test` が含まれる環境だけでシードを実行する。

```bash
pnpm db:test:up
pnpm db:push:test
pnpm db:test:seed
pnpm dev
```

V2入口: `http://localhost:3000/v2/properties`

共通パスワード: `PropFlow-Test-2026!`

| 権限 | メールアドレス |
|---|---|
| 管理者 | `admin@propflow.test` |
| 物件掲載者 | `seller@propflow.test` |
| 閲覧・購入側 | `buyer@propflow.test` |

## 主要シナリオ

1. 掲載者でログインし、V2物件登録から下書き保存する。
2. 下書きを編集して公開し、「物件を公開しました」を確認する。
3. 購入側で検索し、お気に入り追加・解除と一覧反映を確認する。
4. 購入側から問い合わせ、掲載者側で「相手から商談」と表示されることを確認する。
5. 掲載者が要返信を付け、商談一覧の要返信絞り込みを確認する。
6. 掲載者の興味者リストで対象物件を開き、「商談中」「商談を見る」を確認する。
7. 関連資料を追加し、公開・非公開、別タブPDFプレビュー、一括DLを確認する。
8. 紹介資料を生成し、別タブ表示とダウンロード資料への保存を確認する。
9. 閲覧制限へ購入側を追加し、購入側から物件が見えないことを確認する。
10. 閲覧制限を解除し、成約報告・削除の権限が掲載者だけにあることを確認する。

## 端末確認

- PC: 1280px、1440px、1920px
- スマホ: 390px前後のiPhone相当、412px前後のAndroid相当
- 長い物件名・会社名、ブラウザ拡大125%、スマホキーボード表示時も確認する。

## 合格条件

- 旧画面やログイン画面へ意図せず遷移しない。
- 権限外の編集・削除・閲覧ができない。
- 公開、商談、資料、通知の結果が再読み込み後も保持される。
- 本番DBや本番ユーザーへ通知を送信しない。

## 段階公開

1. 社内アカウントだけV2を有効化し、上記シナリオを完走する。
2. 協力会社2〜3社へ限定し、既存画面へ戻せる状態で1週間並行運用する。
3. エラー、問い合わせ、操作完了率を確認して対象会社を段階的に増やす。
4. 問題がないことを確認してV2を標準画面にし、旧画面は一定期間URLを保持する。
5. 旧画面へのアクセスがなくなってから、別作業として旧画面を廃止する。
